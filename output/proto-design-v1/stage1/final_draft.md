## 2. 需求分析摘要

### 2.1 产品定位

产品定位为"**AI 优先接待 + 人工可控接管 + 全渠道统一会话 + 知识驱动回答 + 数据化持续运营**"的多租户 SaaS/私有化客服平台。

### 2.2 本期范围（数据底座版）

V1 数据底座版聚焦以下能力：

1. 全量核心实体的数据增删改查：租户、客服账号、客户、会话、消息、平台配置、角色权限；
2. 多平台协同：平台管理后台、租户运营后台、PC 客服工作台三端界面；
3. Web 网页入口：Web Widget 与独立聊天窗口；
4. 多端实时同步：消息、会话状态、在线状态、未读数量。

AI 问答、知识库、客服路由、运营报表等业务能力在数据底座稳定后二期对接。实时语音、微信/企微、Webhook、移动客服端继续延后。

### 2.3 明确不在本期范围

- 大语言模型预训练、底层训练平台；
- 完整 CRM、ERP、OA 业务系统；
- 金融支付、清结算、完整账务系统；
- 复杂营销自动化、订单履约、电商交易能力。

### 2.4 核心角色（7 类）

| 角色 | 权限层级 | 主要职责 |
| --- | --- | --- |
| 超级管理员 | 平台级 | 管理租户、套餐与配额、平台 AI 模型、全局策略、全局统计与审计 |
| 租户管理员 | 租户级 | 管理本机构客服、客户、知识库、渠道、路由/SLA、隐私与运营规则 |
| 客服主管 | 租户级 | 排班调度、技能组、会话监控、质检、升级处理、绩效与容量管理 |
| 客服人员 | 一线业务 | 接待客户、处理消息、查看授权客户资料、AI 辅助、转接/工单、结束会话 |
| AI 客服 | 系统角色 | 意图识别、知识检索、生成回答、置信度判断、触发追问或转人工 |
| 客户 | 外部用户 | 发起咨询、发送多类型消息、评价、管理自身隐私同意与数据权利请求 |
| 第三方系统 | 外部系统 | 通过 OAuth2/Open API/Webhook 与客服平台交互 |

## 3. 原型设计总览

### 3.1 五大系统全景

基于 PRD 4.1 页面地图与 5.5 初始化流程，将 19 项本期功能拆解到 5 个相互独立又前后承接的系统中。

| 系统 | 名称 | 主要用户 | 功能编号 | 一级菜单 | 二级菜单 |
| --- | --- | --- | --- | --- | --- |
| 系统 1 | 平台管理后台 | 超级管理员 | F-001·F-002·F-003·F-004·F-005·F-018·F-038·F-044 | 4 | 11 |
| 系统 2 | 租户运营后台 | 租户管理员、客服主管 | F-005·F-006·F-010·F-012·F-018·F-029·F-033~F-039 | 8 | 22 |
| 系统 3 | PC 客服工作台 | 客服人员 | F-010·F-019·F-020·F-023~F-026 | 三栏布局 | — |
| 系统 4 | 客户 Web 入口 | 客户 | F-026·F-029·F-030·F-035 | 7 状态 | — |
| 系统 5 | 登录与账号体系 | 全角色 | 7.10 | 5 页面 | — |

### 3.2 系统间协作关系

1. 系统 1 创建租户、配置平台 AI 模型与全局策略（超级管理员）；
2. 租户管理员登录系统 5 → 跳转到系统 2 完成初始化；
3. 系统 2 创建客服账号、配置角色与权限（租户管理员）；
4. 客服登录系统 5 → 进入系统 3 开始接待（客服人员）；
5. 客户通过系统 4 发起咨询（客户）；
6. 消息总线在系统 3 与系统 4 之间实时同步会话与消息；
7. 全部会话、消息、附件、操作日志由数据底座统一记录，可由系统 1/2 检索与审计。

### 3.3 数据底座（共享中台）

数据底座不单独成系统，但贯穿全部 5 大系统，提供横切能力：

- 租户隔离：所有业务对象强制 tenant_id，JWT 携带租户上下文；
- 消息总线：Socket.io 实时通道，多端同步；
- 审计日志：全平台敏感操作流水；
- 权限校验：RBAC + Tenant 双重约束；
- 文件存储：消息附件统一对象存储；
- AI 通道：平台级模型池，租户按需选择。

#### 4.3.1 平台总览 · 全局数据看板（F-004）

| KPI | 说明 |

#### 4.3.2 租户列表（F-001 / F-002）

| 字段 | 类型 / 规则 | 说明 |
| --- | --- | --- |
| 租户 ID | 系统自动 · T + 6 位 | 全局唯一 |
| 租户名称 | 2-30 字 | 支持企业简称 |
| 租户编码 | 3-20 字母数字 | 用于子域名与 API |
| 套餐 | 枚举：体验版/团队版/企业版/旗舰版 | 决定配额上限 |
| 状态 | 枚举：试用中/正常/欠费/已停用/已注销 | 状态机受 RBAC 约束 |
| 坐席配额 / 已用 | 数字 · 进度条 | 使用率 ≥ 80% 红色预警 |

| 知识库容量 / 已用 | GB · 进度条 | — |
| 到期时间 | 日期 | 过期前 15/7/3/1 天提醒 |
| 创建人 / 时间 | 人员 + 时间 | 审计可查 |
| 操作 | 按钮组 | 查看/编辑/启停/续费/配额调整/注销 |

#### 4.3.3 租户详情（F-002）

以 Tab 形式组织 6 个分区：基础信息 / 套餐与配额 / 用量趋势 / 管理员 / 客服团队 / 操作日志。每个 Tab 独立保存；关键字段（编码、状态、配额）变更需二次确认并写入审计。

#### 4.3.4 平台配置 · AI 模型管理（F-003 / F-018）

| 字段 | 说明 |
| --- | --- |
| 模型名称 | 展示名 |
| 提供方 | DeepSeek / 通义千问 / GLM / OpenAI 兼容 / 企业私有 / 自定义 |
| API Endpoint | URL · 必填 · https:// |
| API Key | 加密存储 · 仅显示后四位 |
| 模型标识 | 如 deepseek-chat、qwen-plus |
| 部署模式 | 云端 API / 私有化 / 混合 |
| 支持能力 | 对话 / Embedding / 语音 / 视觉 |
| Token 限速 | TPM / RPM |
| 状态 | 启用 / 停用 / 维护中 |
| 健康检查 | 最后探测时间 / 延迟 / 状态 |

交互规则：提供"测试连通性"按钮（输入 prompt → 返回结果 + 延迟 + token 消耗）；支持模型版本灰度（A/B 5%/50%/100%）。

#### 4.3.5 安全审计 · 操作日志（F-038）

不可修改、可导出 CSV 的流水表。字段：时间 / 操作人 / 操作类型（30 种枚举）/ 目标对象 / 变更前 → 变更后 / 客户端 IP / UA / requestId。顶部多维筛选（时间/操作人/对象类型/关键字），支持按租户维度过滤。

### 5.3 关键页面设计

#### 5.3.1 租户工作台首页（首屏）

欢迎语 + 当前租户套餐与到期日；中部 4 个 KPI（今日会话 / 在线客服 / AI 解决率 / 待处理告警）；下方分两栏：左侧"实时会话动态"（最近 20 条进入 AI 或人工的会话，可点击进入会话详情）、右侧"待办事项"（知识待审 / 客户分群待处理 / 客服工单转交等）。

#### 5.3.2 客服账号管理（F-006）

| 字段 | 说明 |
| --- | --- |
| 姓名 | 必填 · 1-20 字 |
| 登录账号 | 手机号 / 邮箱 · 全租户唯一 |
| 角色 | 多选：租户管理员 / 客服主管 / 客服人员 |

| 入职时间 | 日期 |

交互规则：支持"邀请注册"（生成邀请链接 / 短信，72h 过期）和"重置密码"（强制下次登录改密）。

#### 5.3.3 客户中心 · 客户档案（F-010）

左侧客户列表（搜索 + 标签过滤 + 来源过滤 + 状态过滤），右侧客户详情。详情 Tab 结构：

- 基础资料：姓名 / 手机 / 邮箱 / 来源 / 等级 / 标签 / 备注 / 自定义字段（租户级定义）；
- 历史会话：按时间倒序，点击跳转会话详情；
- 工单：工单列表 + 状态；
- 操作记录：谁在什么时候改了什么字段；
- 隐私请求：导出 / 删除 / 更正请求处理进度。

敏感字段（手机 / 邮箱）按权限脱敏；数据导出走独立"导出"权限，不随查看权限下发。

#### 5.3.5 会话检索（F-037）

#### 5.3.6 操作日志（F-038 租户内）

仅记录本租户内敏感操作（创建客服 / 修改角色 / 删除客户 / 配置变更 / 登录登出）。30/90/365 天可查，可申请 CSV 导出（导出动作本身也记录）。

## 7. 系统 4 · 客户 Web 入口

### 7.1 系统定位

面向客户（外部用户）的咨询入口，包含 Web Widget（嵌入式气泡）和独立聊天窗口两种形态，二者共享同一会话。客户咨询的核心动作是"发起会话 → 收发消息 → 结束 / 评价"，V1 聚焦文字消息与评价。

### 7.2 两种形态

| 形态 | 特点 |
| --- | --- |
| A · Web Widget 嵌入式 | 第三方网站通过 script 引入；右下角悬浮气泡（可配置位置）；点击展开为聊天面板（最大宽 380px · 高 560px）；不打扰页面浏览；移动端可全屏；支持访客识别 |
| B · 独立聊天窗口 | 租户直接打开 {tenant}.support.com 域名；全屏聊天页，含 Header / 消息区 / 输入区；适合无官网或希望直接对话的场景；支持设备指纹 + 自定义标识记住历史会话 |

### 7.3 关键状态

| 状态 | 展示 | 操作 |
| --- | --- | --- |
| 折叠（气泡态） | 右下角悬浮气泡 + 未读小红点 | 点击展开 |
| 欢迎态 | 欢迎语 + 常见问题快捷入口（V1 仅展示） | 输入消息 / 点击 FAQ 预填 |
| AI 接待中 | 客户发送 → AI 思考动效 → 回答 + 引用卡 | 继续输入 / 要求转人工 |

| 离线 | 客服不在线 · 留言表单 | 提交工单 |

### 7.4 消息能力（V1）

- 文本（含 emoji）：单条 ≤ 2000 字；
- 图片（jpg/png/gif）：≤10MB · 自动压缩；
- 文件：≤50MB；
- 评价（V1 简化）：星标 + 文字；
- 语音消息（二期 F-021）。

### 7.5 隐私与同意（F-041）

- 首次进入时弹隐私声明（租户可配置文案）；
- 勾选后才能发起咨询；
- 用户可随时通过侧边入口查看、撤回同意、申请数据导出/删除；
- 客服看到"用户已撤回同意"时该客户档案自动脱敏。

### 7.6 评价（F-026 V1 简化）

会话结束后 5 分钟内客户可评价：1-5 星 + 标签多选（"响应及时" / "专业" / "态度好" / "解决问题" / "不满意"）+ 50 字内文字。不评价则视为放弃，不强制打扰。

### 8.1 系统定位

覆盖全 7 角色的统一认证入口。V1 必做（PRD 7.10），包括登录、邀请注册、密码管理、Token 刷新、RBAC 鉴权。

### 8.2 关键页面

## 9. 核心流程与状态机

### 9.1 会话状态机

贯穿系统 3（工作台）与系统 4（客户入口）的核心状态机。状态变化必须在 UI 上明确可见，并写入操作日志。

| 状态 | 含义 | 进入条件 | 离开条件 |
| --- | --- | --- | --- |
| NEW 待接入 | 渠道已创建会话 | 客户首次消息 | 进入 AI_HANDLING |
| AI_HANDLING AI 接待中 | AI 处理中 | 新会话 / 人工不可用回退 | AI 解决 → 结束；转人工 → QUEUED |
| QUEUED 排队中 | 等待人工客服 | 低置信度 / 客户要求 / 策略触发 | 分配成功 → HUMAN_HANDLING；超时回 AI / 升级 |
| HUMAN_HANDLING 人工接待中 | 人工已接管 | 客服确认接管 | 转接 / 结束 / 工单协同 |
| TRANSFERRED 已转接 | 会话转交其他客服 / 技能组 | 人工转接 / 升级 | 新客服接管 |
| ENDED 已结束 | 服务已结束 | AI 或人工完成 / 客户结束 / 超时 | 触发评价 |
| EVALUATED 已评价 | 客户已评价 | 客户评价 | 终态 |

### 9.2 租户初始化流程（5.5，上线必经路径）

1. 超级管理员创建租户并配置套餐与配额（系统 1）；
2. 租户管理员首次登录并设置密码（系统 5 → 系统 2）；
3. 创建客服团队（账号、角色、技能组）（系统 2 客服与组织）；
4. 上传知识库（FAQ / PDF / Word / Markdown）（系统 2 知识库占位）；
5. 配置 AI 模型与回答策略（系统 2 AI 配置）；
6. 发布客服入口（Web Widget / 网页聊天窗口）（系统 2 渠道与开放）；
7. 客户发起咨询（系统 4 → 客户咨询主流程）。

任一环节失败均应给出明确提示并支持重试；租户未完成初始化时，客服入口不应对外可见。

### 9.3 客户咨询主流程（5.1）

1. 客户从 Web 网页客服入口发起咨询（系统 4）；
2. 渠道适配层统一消息格式并创建 / 恢复会话；
3. 新会话默认进入 AI 接待：意图识别 → RAG 检索 → 上下文组装 → LLM 生成；
4. AI 护栏：置信度、引用、高风险 / 禁答 → 直接回复 / 追问 / 阻断 / 转人工；
5. 需要人工时进入会话路由：技能组 → 在线客服 → 负载 / 轮询 / VIP / 熟客 → 排队；
6. 人工客服接管后获得摘要、上下文、客户信息、转人工原因 + AI 辅助（系统 3）；
7. 问题解决后结束会话，向客户触发评价（系统 4）；
8. 会话 / 消息 / 附件 / AI 轨迹 / 转接 / 评价 / 审计全部保存，进入运营统计。

### 9.4 AI 转人工触发条件（F-015）

- AI 置信度低于场景阈值；
- 连续多次无法回答或知识未命中；
- 客户明确要求人工；
- 命中敏感 / 高风险 / 投诉 / 禁答规则；
- AI / 知识检索 / 模型依赖异常；
- 租户配置的业务规则主动要求人工。

### 9.5 人工接管要求（5.4）

- 转人工必须携带历史聊天记录 + 客户信息 + AI 会话摘要 + 用户问题摘要 + 转人工原因；
- 摘要生成失败时必须展示原始消息，不得阻塞接管；
- 同一会话仅允许一个主接待者处于发送权限状态；
- 接管超时触发 SLA 提醒 / 升级。

## 10. 数据与权限设计

### 10.1 权限设计原则（RBAC + Tenant 双重约束）

1. 用户先经角色授权，再受租户数据域限制；
2. 所有租户级业务对象必须包含 tenant_id（或等价租户上下文）；
3. JWT 携带 user_id、tenant_id、role、permissions；数据访问层再次强制注入 tenant_id；
4. 超级管理员跨租户操作必须显式切换租户上下文并记录原因；
5. 敏感字段按照角色返回脱敏值或完全省略；数据导出采用独立权限；
6. 客户只能查看和控制自身数据与隐私偏好，不暴露内部规则与其他客户信息。
