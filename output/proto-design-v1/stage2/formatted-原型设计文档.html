执行摘要

本设计文档基于 PRD V1.2 与第一期产品思维导图，将 19 项本期功能 拆解为 5 大系统：平台管理后台（超级管理员）、租户运营后台（租户管理员/客服主管）、PC 客服工作台（客服人员）、客户 Web 入口（客户）、登录与账号体系（全角色）。

V1 聚焦"数据底座 + 三端协同"：核心实体增删改查、Web Widget 入口、多端实时同步；AI、知识库、客服路由、运营报表等业务能力在数据底座稳定后二期对接，本期以占位 + 接口预留形式呈现。

2. 需求分析摘要

本章从定位、范围、角色与形态四个维度概述产品，作为原型设计的输入基线。

2.1 产品定位

产品定位为"AI 优先接待 + 人工可控接管 + 全渠道统一会话 + 知识驱动回答 + 数据化持续运营"的多租户 SaaS/私有化客服平台。

2.2 本期范围（数据底座版）

  • 全量核心实体的数据增删改查：租户、客服账号、客户、会话、消息、平台配置、角色权限；
  • 多平台协同：平台管理后台、租户运营后台、PC 客服工作台三端界面；
  • Web 网页入口：Web Widget 与独立聊天窗口；
  • 多端实时同步：消息、会话状态、在线状态、未读数量。

AI 问答、知识库、客服路由、运营报表等业务能力在数据底座稳定后二期对接。实时语音、微信/企微、Webhook、移动客服端继续延后。

2.3 明确不在本期范围

  • 大语言模型预训练、底层训练平台；
  • 完整 CRM、ERP、OA 业务系统；
  • 金融支付、清结算、完整账务系统；
  • 复杂营销自动化、订单履约、电商交易能力。

3.1 五大系统全景

基于 PRD 4.1 页面地图与 5.5 初始化流程，将 19 项本期功能拆解到 5 个相互独立又前后承接的系统中。

3.2 系统间协作关系

  1. 系统 1 创建租户、配置平台 AI 模型与全局策略（超级管理员）；
  2. 租户管理员登录系统 5 → 跳转到系统 2 完成初始化；
  3. 系统 2 创建客服账号、配置角色与权限（租户管理员）；
  4. 客服登录系统 5 → 进入系统 3 开始接待（客服人员）；
  5. 客户通过系统 4 发起咨询（客户）；
  6. 消息总线在系统 3 与系统 4 之间实时同步会话与消息；
  7. 全部会话、消息、附件、操作日志由数据底座统一记录，可由系统 1/2 检索与审计。

3.3 数据底座（共享中台）

数据底座不单独成系统，但贯穿全部 5 大系统，提供横切能力：

  • 租户隔离：所有业务对象强制 tenant_id，JWT 携带租户上下文；
  • 消息总线：Socket.io 实时通道，多端同步；
  • 审计日志：全平台敏感操作流水；
  • 权限校验：RBAC + Tenant 双重约束；
  • 文件存储：消息附件统一对象存储；
  • AI 通道：平台级模型池，租户按需选择。

9. 核心流程与状态机

本章定义贯穿全端的状态机与两条核心业务流程，是交互设计的依据。

9.1 会话状态机

贯穿系统 3（工作台）与系统 4（客户入口）的核心状态机。状态变化必须在 UI 上明确可见，并写入操作日志。

状态含义进入条件离开条件
NEW 待接入渠道已创建会话客户首次消息进入 AI_HANDLING
AI_HANDLING AI 接待中AI 处理中新会话 / 人工不可用回退AI 解决 → 结束；转人工 → QUEUED
QUEUED 排队中等待人工客服低置信度 / 客户要求 / 策略触发分配成功 → HUMAN_HANDLING；超时回 AI / 升级
HUMAN_HANDLING 人工接待中人工已接管客服确认接管转接 / 结束 / 工单协同
TRANSFERRED 已转接会话转交其他客服 / 技能组人工转接 / 升级新客服接管
ENDED 已结束服务已结束AI 或人工完成 / 客户结束 / 超时触发评价
EVALUATED 已评价客户已评价客户评价终态

9.2 租户初始化流程（5.5，上线必经路径）

  1. 超级管理员创建租户并配置套餐与配额（系统 1）；
  2. 租户管理员首次登录并设置密码（系统 5 → 系统 2）；
  3. 创建客服团队（账号、角色、技能组）（系统 2 客服与组织）；
  4. 上传知识库（FAQ / PDF / Word / Markdown）（系统 2 知识库占位）；
  5. 配置 AI 模型与回答策略（系统 2 AI 配置）；
  6. 发布客服入口（Web Widget / 网页聊天窗口）（系统 2 渠道与开放）；
  7. 客户发起咨询（系统 4 → 客户咨询主流程）。

任一环节失败均应给出明确提示并支持重试；租户未完成初始化时，客服入口不应对外可见。

9.3 客户咨询主流程（5.1）

  1. 客户从 Web 网页客服入口发起咨询（系统 4）；
  2. 渠道适配层统一消息格式并创建 / 恢复会话；
  3. 新会话默认进入 AI 接待：意图识别 → RAG 检索 → 上下文组装 → LLM 生成；
  4. AI 护栏：置信度、引用、高风险 / 禁答 → 直接回复 / 追问 / 阻断 / 转人工；
  5. 需要人工时进入会话路由：技能组 → 在线客服 → 负载 / 轮询 / VIP / 熟客 → 排队；
  6. 人工客服接管后获得摘要、上下文、客户信息、转人工原因 + AI 辅助（系统 3）；
  7. 问题解决后结束会话，向客户触发评价（系统 4）；
  8. 会话 / 消息 / 附件 / AI 轨迹 / 转接 / 评价 / 审计全部保存，进入运营统计。

9.4 AI 转人工触发条件（F-015）

  • AI 置信度低于场景阈值；
  • 连续多次无法回答或知识未命中；
  • 客户明确要求人工；
  • 命中敏感 / 高风险 / 投诉 / 禁答规则；
  • AI / 知识检索 / 模型依赖异常；
  • 租户配置的业务规则主动要求人工。

9.5 人工接管要求（5.4）

  • 转人工必须携带历史聊天记录 + 客户信息 + AI 会话摘要 + 用户问题摘要 + 转人工原因；
  • 摘要生成失败时必须展示原始消息，不得阻塞接管；
  • 同一会话仅允许一个主接待者处于发送权限状态；
  • 接管超时触发 SLA 提醒 / 升级。

10. 数据与权限设计

本章定义 RBAC + Tenant 双重权限约束与核心数据对象。

10.1 权限设计原则（RBAC + Tenant 双重约束）

  1. 用户先经角色授权，再受租户数据域限制；
  2. 所有租户级业务对象必须包含 tenant_id（或等价租户上下文）；
  3. JWT 携带 user_id、tenant_id、role、permissions；数据访问层再次强制注入 tenant_id；
  4. 超级管理员跨租户操作必须显式切换租户上下文并记录原因；
  5. 敏感字段按照角色返回脱敏值或完全省略；数据导出采用独立权限；
  6. 客户只能查看和控制自身数据与隐私偏好，不暴露内部规则与其他客户信息。
