0项目背景

产品定位："AI 优先接待 + 人工可控接管 + 全渠道统一会话 + 知识驱动回答 + 数据化持续运营" 的多租户 SaaS/私有化客服平台。
V1 数据底座版聚焦 全量核心实体的数据增删改查（租户/客服账号/客户/会话/消息/平台配置/角色权限）+ 三端界面协同（平台管理后台 · 租户运营后台 · PC 客服工作台）+ Web 网页入口 + 多端实时同步。 AI/知识库/客服路由/运营报表等业务能力在数据底座稳定后二期对接。

系统间协作关系

①系统 1 创建租户、配置平台 AI 模型与全局策略 超级管理员
②租户管理员登录系统 5 → 跳转到系统 2 完成初始化 租户管理员
③系统 2 创建客服账号、配置角色与权限 租户管理员
④客服登录系统 5 → 进入系统 3 开始接待 客服人员
⑤客户通过系统 4 发起咨询 客户
⑥消息总线在系统 3 与系统 4 之间实时同步会话与消息
⑦全部会话、消息、附件、操作日志由数据底座统一记录，可由系统 1/2 检索与审计

2设计原则

一、租户隔离是设计基线所有业务对象强制 tenant_id，JWT 携带租户上下文，数据访问层二次注入；超级管理员跨租户操作需显式切换并记审计。
二、菜单即权限边界RBAC 与菜单/路由双向绑定，权限变更立刻反映在侧边栏可见性；未授权路由 403 而非 404。
三、状态可见、流转可追会话、AI、工单统一带状态徽章和操作日志；状态机（NEW→AI_HANDLING→QUEUED→HUMAN_HANDLING→TRANSFERRED→ENDED→EVALUATED）贯穿全端。
四、数据底座优先，业务延后本期所有页面聚焦"增删改查 + 列表筛选 + 详情 + 审计"，复杂业务（AI 回答、知识运营、报表分析）通过占位 + 数据接口预留，二期无缝接入。
五、三端视觉一致但密度不同平台/租户后台追求高密度表格与看板；工作台追求高效操作（快捷键、批量、状态色）；客户入口追求轻量、温暖、可信任。
六、关键操作可回滚删租户、停客服、撤权限、关知识库 → 全部走"软删除 + 二次确认 + 审计"路径，不提供不可逆的危险按钮。

3系统 1 · 平台管理后台

系统定位：面向 超级管理员（平台级）使用，承担"管租户、控资源、设模型、看大盘、查审计"五大职责，是 SaaS 多租户治理的"驾驶舱"。 所有租户级业务对象都从该系统向下授权；本系统不参与具体客服业务。

6系统 4 · 客户 Web 入口

系统定位：面向 客户（外部用户）的咨询入口，包含 Web Widget（嵌入式气泡） 和 独立聊天窗口 两种形态，二者共享同一会话。客户咨询的核心动作是"发起会话 → 收发消息 → 结束 / 评价"，V1 聚焦文字消息与评价。

两种形态

A · Web Widget 嵌入式

  • 第三方网站通过 <script> 引入
  • 页面右下角悬浮气泡（可配置位置）
  • 点击展开为聊天面板（最大宽 380px · 高 560px）
  • 不打扰页面浏览；移动端可全屏
  • 支持 访客识别（匿名 / 登录态 / 自定义透传）

B · 独立聊天窗口

  • 租户直接打开 {tenant}.support.com 域名
  • 全屏聊天页，含 Header / 消息区 / 输入区
  • 适合无官网或希望直接对话的场景
  • 支持设备指纹 + 自定义标识记住历史会话

关键页面 / 状态

状态展示操作
折叠（气泡态）右下角悬浮气泡 + 未读小红点点击展开
欢迎态欢迎语 + 常见问题快捷入口（V1 仅展示）输入消息 / 点击 FAQ 预填

消息能力（V1）

  • 文本（含 emoji）· 单条 ≤ 2000 字
  • 图片（jpg/png/gif · ≤10MB · 自动压缩）
  • 文件（≤50MB）
  • 评价（V1 简化为星标 + 文字）
  • 语音消息（二期 F-021）

隐私与同意（F-041）

  • 首次进入时弹隐私声明（租户可配置文案）
  • 勾选后才能发起咨询
  • 用户可随时通过侧边入口查看、撤回同意、申请数据导出/删除
  • 客服看到"用户已撤回同意"时该客户档案自动脱敏

评价（F-026 V1 简化）

会话结束后 5 分钟内客户可评价：1-5 星 + 标签多选（"响应及时" / "专业" / "态度好" / "解决问题" / "不满意"） + 50 字内文字。不评价则视为放弃，不强制打扰。

原型入口：客户聊天窗口

系统定位：覆盖全 7 角色的统一认证入口。V1 必做（PRD 7.10），包括登录、邀请注册、密码管理、Token 刷新、RBAC 鉴权。

AI 转人工触发条件（F-015）

  • AI 置信度低于场景阈值
  • 连续多次无法回答或知识未命中
  • 客户明确要求人工
  • 命中敏感 / 高风险 / 投诉 / 禁答规则
  • AI / 知识检索 / 模型依赖异常
  • 租户配置的业务规则主动要求人工

人工接管要求（F-015 · 5.4）

  • 转人工必须携带 历史聊天记录 + 客户信息 + AI 会话摘要 + 用户问题摘要 + 转人工原因
  • 摘要生成失败时必须展示原始消息，不得阻塞接管
  • 同一会话仅允许一个主接待者处于发送权限状态
  • 接管超时触发 SLA 提醒 / 升级

9租户初始化流程（5.5）

产品上线的必经路径。任一环节失败均应给出明确提示并支持重试；租户未完成初始化时，客服入口不应对外可见。

①超级管理员创建租户并配置套餐与配额 系统 1
②租户管理员首次登录并设置密码 系统 5 → 系统 2
③创建客服团队（账号、角色、技能组）系统 2 客服与组织
④上传知识库（FAQ / PDF / Word / Markdown）系统 2 知识库（占位）
⑤配置 AI 模型与回答策略 系统 2 AI 配置
⑥发布客服入口（Web Widget / 网页聊天窗口）系统 2 渠道与开放
⑦客户发起咨询 系统 4 → 流程 10

10客户咨询主流程（5.1）

①客户从 Web 网页客服入口发起咨询 系统 4
②渠道适配层统一消息格式并创建 / 恢复会话
③新会话默认进入 AI 接待：意图识别 → RAG 检索 → 上下文组装 → LLM 生成
④AI 护栏：置信度、引用、高风险 / 禁答 → 直接回复 / 追问 / 阻断 / 转人工
⑤需要人工时进入会话路由：技能组 → 在线客服 → 负载 / 轮询 / VIP / 熟客 → 排队
⑥人工客服接管后获得摘要、上下文、客户信息、转人工原因 + AI 辅助 系统 3
⑦问题解决后结束会话，向客户触发评价 系统 4
⑧会话 / 消息 / 附件 / AI 轨迹 / 转接 / 评价 / 审计全部保存，进入运营统计
